# pattern-cad 개발 계획

> 초안. 이 문서를 직접 고쳐 주시면 그 내용을 기준으로 진행합니다.

## 0. 목표

2D 패턴 CAD (제도 · 그레이딩 · 마카) + **카테고리 · 핏 · 디테일 선택 → 기본원형 자동 생성**.

경쟁 프로그램(유까캐드, 스타일캐드, 렉트라)과 같은 자리에서 쓰이되, "빈 화면에서 시작"이 아니라
"원형이 이미 그려진 상태에서 시작"하게 만드는 것이 차별점이다.

## 1. 핵심 설계 원칙 — 점과 선에 이름이 있다

컴퓨터 제도에서는 순서가 중요하지 않다. 점을 좌표로 찍고, 선을 잇고, 곡선은 나중에 움직이면 된다.
대신 **모든 점과 선이 무엇인지(진동깊이점, 어깨끝점, 옆목점, 엉덩이선…)가 프로그램 안에 남아 있어야** 한다.
그래야:

- 치수가 바뀌면 관련된 점만 옮겨 원형이 다시 그려진다 (자동 생성의 전제)
- "어깨너비 +1/2”" 같은 디테일 조작이 "어깨끝점을 옆으로 1/2” 이동"으로 정의된다
- 그레이딩 편차를 "어깨끝점 x +1/8”" 처럼 점 이름에 붙일 수 있다
- 조각의 어느 변이 옆솔기고 어디가 암홀인지 알아서 노치·시접·마카 결방향이 자동으로 따라온다

좌표만 저장하는 CAD(DXF)는 이 정보를 잃는다. 그래서 내부 포맷은 좌표가 아니라 **이름 + 규칙**으로 저장하고,
DXF는 내보내기/가져오기용으로만 쓴다.

### 1.1 자료 구조 (아래층부터)

| 층 | 무엇 | 예 |
|---|---|---|
| 치수 (Measurements) | 신체 치수 + 여유 = 패턴 치수 | `B=33.1/2, 여유=2.1/2 → 패턴 B=36` |
| 점 (Points) | 이름 + 정의 규칙 | `BL_SS: BL_CB에서 왼쪽으로 B/4 + 여유/4` |
| 선 (Lines) | 두 점(이상)을 잇는 직선/곡선 + 역할 | `암홀: SP → 뒤품점 → 겨드랑점, 곡선, 외곽선` |
| 원형 (Block) | 치수 → 점 → 선의 규칙 묶음 | 시추니 기본 원형, 스커트 원형, 팬츠 원형, 소매 원형 |
| 조작 (Operations) | 원형을 스타일로 바꾸는 연산 | 다트 이동, 절개-벌림, 옆솔기 이동, 기장 변경, 턱 넣기 |
| 스타일 (Style) | 원형 + 조작 목록 + 부속 | 오버사이즈 블라우스 = 시추니 무다트 원형 + 어깨 확장 + 셔츠칼라 + 커프스 |
| 조각 (Piece) | 스타일에서 잘라낸 재단 단위 | 앞판, 뒤판, 소매, 칼라, 안단(미까시) — 시접·식서·노치·매수 |
| 그레이딩 (Grading) | 사이즈별 점 편차 또는 치수 재대입 | 55 → 66: 어깨끝점 x +1/4” |
| 마카 (Marker) | 조각을 원단 폭에 배치 | 폭 58”, 결 방향, 매수, 요척 |

### 1.2 점 정의 규칙 (점을 "어떻게 구하는가")

| 규칙 | 뜻 | 예 |
|---|---|---|
| origin | 기준점 | 뒤목점 = (0, 0) |
| offset | 어떤 점에서 x/y로 이동 | 뒤중심 가슴선점 = 뒤목점에서 아래로 `진동깊이` |
| along | 선 위에서 거리 또는 비율 | 견갑점 = 옆목점에서 옆으로 1.1/2”, 아래로 4” |
| intersect | 두 선의 교점 | 겨드랑점 = 옆솔기선 × 가슴선 |
| perpendicular | 점에서 선에 내린 수선의 발 | |
| on_curve | 곡선 위 길이 지점 | 노치 = 암홀 곡선 시작에서 3” |
| mirror | 대칭 | |

값 자리에는 숫자나 치수 이름 식(`B/4 + 여유/4`, `등길이 - 1/2`)이 들어간다.

### 1.3 선 역할

| 역할 | 뜻 |
|---|---|
| outline (외곽선/완성선) | 조각의 완성 윤곽 |
| seam_allowance (시접선) | 재단선. 외곽선에서 시접만큼 오프셋 |
| construction (안내선/기초선) | 제도용. 인쇄·재단 안 함 |
| dart (다트) | 다트 두 변 + 중심 + 끝점 |
| slash (절개선) | 전개용 |
| fold (골선) | |
| grain (식서) | 결 방향 |
| notch (노치) | |
| mark (표시) | 지퍼끝, 겹트임, 단추, 주머니 위치, 스티치 |
| dimension (치수선) | 도면 주석. 원형 자체엔 영향 없음 |

곡선은 **3차 베지어**로 저장한다. 통과점은 이름 있는 점이고, 핸들은 UI에서 잡아당길 수 있다.
치수가 바뀌면 통과점이 움직이고 핸들은 상대 비율로 따라간다.

## 2. 단계

### 0단계 — 데이터 확보 ✅
포트폴리오 PDF에서 42개 아이템의 패턴 선·치수·유의사항 추출 (`extracted/`).

### 1단계 — 원형 정의 언어 + 시추니 기본 원형
- 명칭 사전 확정 (위 1.4)
- 원형 파일 포맷(YAML) 확정: 치수 → 점 규칙 → 선 → 곡선
- `core/` 기하 엔진: 점·직선·베지어, 길이, 교점, 오프셋, 수선
- 시추니 기본 원형(앞판·뒤판)을 규칙으로 작성 → SVG로 그림 → **원본 도면 위에 겹쳐 검증**
- 산출물: `blocks/sichuni_basic.yaml`, `core/`, 검증 그림

여기서 나오는 규칙 파일이 프로그램 전체의 뼈대라, 이 단계에서 포맷을 잘 잡는 게 제일 중요하다.

### 2단계 — 원형 확장
시추니 무다트 원형, 소매 원형, 스커트 원형(제허리), 팬츠 원형(제허리). 전부 원본과 겹쳐 검증.
이 다섯 개면 포트폴리오 42종 대부분을 전개할 수 있다.

### 3단계 — 조작(전개) 엔진
원형을 스타일로 바꾸는 연산: 다트 이동/분산/삭제, 절개-벌림(플레어·게더·플리츠), 옆솔기 이동,
어깨/품 확장(오버사이즈), 기장·허리 위치 변경, 턱, 요크 절개, 부속 생성(칼라·커프스·오비·안단).
포트폴리오 아이템 몇 개를 "원형 + 조작 목록"으로 재현해 검증.

### 4단계 — 자동 생성 규칙
- **핏 → 여유량 표**: 포트폴리오의 신체/패턴 사이즈 차이가 곧 아이템별 여유량이다. 이를 타이트/레귤러/오버 같은 단계로 정리
- **카테고리 × 핏 × 디테일 → 원형 + 조작 목록** 매핑 표
- 이 표만 채우면 새 아이템이 추가되는 구조

### 5단계 — 조각화 · 파일 입출력
시접·노치·식서·조각명·매수, 안단/심지 표시. DXF(AAMA/ASTM) 내보내기·가져오기, 유까캐드와 왕복 확인. SVG/PDF 출력.

### 6단계 — 그레이딩
사이즈 체계(55 기준) 정의. 두 방식 지원: (a) 점별 편차 규칙 (업계 방식, 포트폴리오 그레이딩 페이지에서 편차 추출 가능),
(b) 치수 재대입 (규칙 기반이라 가능한 방식 — 사이즈별 치수만 넣으면 원형이 다시 그려짐).

### 7단계 — 마카
원단 폭·결·매수 설정, 수동 배치 → 자동 네스팅(무거운 계산이라 나중에 서버로 뺄 수 있게 분리), 요척 계산, 플로터 출력(HPGL/DXF).

### 8단계 — 데스크톱 UI
PySide6(Qt). 캔버스(확대·이동·층), 점 선택·이동, 곡선 핸들 조작, 치수 입력 패널, 원형 선택 마법사(카테고리·핏·디테일),
조각 목록, 마카 화면. `core/`가 화면 없이 완결돼 있으므로 UI는 껍데기다.

UI를 8단계에 뒀지만, **곡선을 손으로 만져보는 최소 화면은 1~2단계쯤 일찍 만드는 게 좋다** — 규칙으로 그린 원형이
손맛에 맞는지 빨리 확인해야 하므로.

## 3. 기술

- Python 3.11+. `core/`는 순수 파이썬(외부 의존 최소), 단위는 내부적으로 인치 소수, 표시는 인치 분수/cm/mm 전환
  (cm_inch 저장소의 `convert.py` 재사용)
- 원형·스타일 파일: YAML (사람이 읽고 고칠 수 있게)
- 프로젝트 파일: JSON
- 테스트: 규칙 → 그림 → 원본 겹침 자동 비교
- UI: PySide6. 개발은 로컬 PC, `core/`·`io/`는 클라우드 세션에서도 진행 가능

## 4. 확정된 사항

| 항목 | 결정 |
|---|---|
| 사이즈 체계 | 한 체계가 아니라 **여러 표기(55/66, S/M/L/XL, 130 등)를 선택**할 수 있어야 하고, 그중 **기준 사이즈를 사용자가 고른다**. 내부는 치수 표(사이즈명 → 치수)로 두고 표기는 껍데기 |
| 핏 단계 | 타이트 / 레귤러 / 루즈 / 오버 4단계. 원형이 나온 뒤 손으로 고칠 수 있으므로 단계는 이 정도로 |
| 디테일 옵션 | 아이템별로 너무 다양하니 **기본적인 것부터 폭넓게** 넣는다 (칼라·소매·커프스·다트/턱·기장·포켓 등) |
| 파일 연동 | **DXF** 로 충분 (대부분의 CAD 가 DXF 연동) |
| 개발 순서 | **상의 → 스커트 → 팬츠 → 아우터** |
| 명칭 | 개발 중간중간 현장 용어로 교정 |
| 첫 원형 | 시추니 기본 원형 (완료 — `blocks/sichuni_basic.yaml`, 원본 대비 최대 편차 0.14″) |

## 5. 진행 기록

- 0단계 완료: `extracted/` (42 아이템)
- 1단계: 규칙 엔진 `patterncad/` (units · geometry · expr · block · svg), 시추니 기본 원형 규칙화, 원본 겹침 검증 `tools/verify_block.py`
- 2단계 진행 중: 원형 상속(`extends`), 시추니 무다트 원형 (p.46 형태 검증 완료, 표기 치수 적용). 다음은 소매 원형
